## Added acceptance coverage

`internal/observability/recorder_http_test.go` verifies that request instrumentation preserves the optional `http.Flusher` contract instead of falsely advertising streaming support. `internal/observability/recorder_test.go` also verifies that failed durable writes increment the cumulative `persistence_failures` counter exposed by `/admin/stats`; raw database error text is deliberately not exposed.

`internal/storage/request_logs_integration_test.go` exercises the production
`OpenSQLiteRuntime` path using the registered `modernc.org/sqlite` driver. It checks:

- Embedded migrations 001–005 are applied exactly once.
- Completed and interrupted request records persist with token usage metadata.
- Summary totals count interrupted requests as errors and distinguish known/final usage.
- Provider/Model breakdowns aggregate request and token totals.
- Closing and reopening the database preserves request records and migration state.

`.github/workflows/ci.yml` runs module download/verification, gofmt, all tests,
race tests, vet, and executable build on GitHub Actions.

## Remaining release gates

1. Run `go mod download` in a network-enabled environment and commit the generated,
   verified `go.sum`; do not fabricate checksums.
2. Run `go test ./...` and `go test -race ./...` with the real SQLite driver.
3. Run the GitHub Actions workflow and retain its result.
4. Exercise at least one real non-streaming request and one real SSE request against
   a configured upstream Provider; verify the provider-reported usage and persisted
   Provider/Model attribution in `/admin/usage` and `/admin/requests`.
5. Verify client cancellation and upstream premature EOF against a live or controlled
   network transport, then sign off the release.
6. Confirm `/admin/stats` reports a nonzero `persistence_failures` value when the
   request-log sink is deliberately made unavailable, and returns to a stable count
   after storage is restored (the counter is cumulative for the process lifetime).

Until all six gates pass, describe R3.2 as implementation-complete with validation
pending, not production-ready.

## Lifecycle consistency correction (2026-11-04)

The recorder now applies a fallback lifecycle classification when a handler emits
an HTTP 4xx/5xx response but leaves the default lifecycle value untouched: the
record is stored as `failed`, not `completed`. Explicit classifications such as
`interrupted` and `timeout` are preserved. The panic recovery path now records
`failed` with `error_code=handler_panic`, including the case where response headers
were already committed with HTTP 200 before the panic. Regression tests cover both
cases. The targeted Observability/Gateway/Provider/TokenUsage tests and race tests
pass in the compile-check environment described above.


## Request-history API consistency correction (2026-11-04)

The repository and `/admin/requests` now share `storage.MaxRecentRequestLogs` (1,000). Requests above the repository cap are clamped to 1,000 instead of unexpectedly falling back to 100. Persisted history ordering now uses `created_at DESC, id DESC`, making equal-timestamp results deterministic. The real SQLite integration test inserts 1,001 equal-timestamp records and checks both the cap and tie-break ordering; it is compiled in the local stub environment but cannot be executed until the real SQLite driver is available.

## SQLite transient-lock recovery coverage (2026-11-04)

Added `TestRequestLogWritesRecoverAfterSQLiteLockIsReleased`. It opens the
production SQLite runtime, holds a write reservation on a second pinned SQL
connection, verifies a request-log append fails within the configured busy
window, releases the reservation, and verifies a subsequent append succeeds
and is queryable. This is an integration test against the real registered
`modernc.org/sqlite` driver and is compiled but NOT EXECUTED in the current
network-restricted environment. It specifically tests recovery after a
transient external SQLite writer lock; it does not claim recovery from disk
corruption, I/O failure, or database replacement.

## Token-count integer-width correction (2026-11-04)

`RequestLog.InputTokens` and `RequestLog.OutputTokens` now use `*int64`, matching
provider usage parsing, the SQLite INTEGER representation, and aggregate counters.
The persistence adapter no longer narrows provider-reported `int64` values to the
platform-sized `int` type. Added
`TestRequestLogPreservesInt64TokenCounts`, which round-trips values above the
signed 32-bit range through the real SQLite repository. The new test is compile-
checked but NOT EXECUTED until the real SQLite driver is available. The non-SQLite
targeted unit tests, race tests, `go vet`, and executable build pass in the local
compile-check environment with the SQLite stub; this does not satisfy the real
SQLite release gate.

## Inference-only usage accounting correction (2026-11-04)

All HTTP traffic remains in `/admin/requests`, but `usage_eligible` now distinguishes
model inference from health checks, model discovery, and administrative endpoints.
`/admin/usage` and provider/model breakdowns filter to inference endpoints only.
Migration 005 defaults historical rows to ineligible because their route cannot be

## Provider token-value validation hardening (2026-11-04 08:34 UTC)

Provider usage parsers now reject negative input, output, and total token counts
for OpenAI-compatible, Anthropic, and Gemini usage envelopes. The Anthropic
input-plus-output derived total is checked for signed `int64` overflow before
addition. Invalid usage is not merged into the request record or persisted.
Streaming usage parse failures are now surfaced as `usage_parse_error` in request
history while preserving the inference request's successful lifecycle when the
upstream stream itself terminates normally.

Regression tests cover negative fields across all three protocol parsers,
Anthropic total overflow, and a completed SSE request containing negative usage.
The TokenUsage, Observability, OpenAI Provider, and non-SQLite Gateway tests pass;
the same four test groups pass under the race detector. All packages and test
files compile with the compile-only SQLite stub, and `go vet ./...` plus
`go build ./cmd/omnirouter` pass in that same stub environment. These checks do
not execute real SQLite integration tests and do not change the outstanding
real-driver release gate.

## Persistence-boundary token validation (2026-11-04 08:49 UTC)

Added defensive validation in `RequestLogRepository.Append`: negative input or
output token counts are rejected before any database operation. This protects
the durable accounting invariant even when a future caller bypasses the
provider protocol parsers and writes directly through the repository. Added
`TestRequestLogAppendRejectsNegativeTokenCountsBeforeDatabaseAccess`; this test
executes successfully without a SQLite driver because rejection occurs before
the DBTX is accessed. Storage, TokenUsage, Observability, OpenAI Provider, and
selected non-SQLite Gateway tests pass in the local stub environment; selected
core tests also pass under `-race`. Full SQLite repository and Gateway
integration tests remain unexecuted until the real driver is available.

## Usage aggregate overflow and snapshot consistency (2026-11-04 08:52 UTC)

SQLite integer `SUM()` fails with an integer-overflow error when a token total
exceeds signed `int64`; it does not wrap the value. The repository now wraps
these failures with an explicit aggregate/possible-overflow context, and the
`/admin/usage` handler returns a generic storage error rather than emitting a
corrupted total. Added `TestUsageAggregatesFailClosedOnInt64Overflow` for the
real SQLite driver; it verifies summary, provider/model breakdown, and combined
usage report all fail closed when valid individual rows exceed the aggregate
range. This integration test is compile-checked only until the real driver is
available.

The repository also exposes `UsageReport`, which reads summary and
provider/model breakdown inside one read transaction. `/admin/usage` now uses
that method so concurrent appends cannot make the summary and breakdown
represent different database snapshots. Stub compile and non-SQLite tests do
not constitute real SQLite transaction or overflow validation.

## Recorder statistics snapshot consistency (2026-11-04 08:54 UTC)

`Recorder.Snapshot()` now copies lifetime counters, in-flight count,
persistence-failure count, and the bounded latency/status window while holding
one read lock. The prior implementation obtained the ring-buffer window and
lifetime counters under separate locks, so a request could complete between
those reads and produce a mixed-time `/admin/stats` snapshot. Added
`TestSnapshotUsesOneConsistentRecorderSnapshot` to verify lifetime totals remain
separate from the bounded window after ring-buffer rollover.

The full package/test compile check, TokenUsage/Observability/OpenAI Provider
unit tests, selected non-SQLite Gateway tests, core race tests, `go vet`, and
`go build` pass in the local compile-only SQLite-stub environment. The Gateway
SQLite integration test is intentionally excluded from execution under the
stub; the real SQLite driver, remote CI, and live Provider acceptance gates
remain outstanding.

## Transaction panic cleanup (2026-11-04 08:54 UTC)

A transaction lifecycle audit found that `SQLStore.WithTx` and `InTransaction`
previously scheduled rollback only when the callback returned an error. A panic
leaves the named error value nil, so that cleanup path could be skipped and a
single-connection SQLite pool could remain occupied by an open transaction.
Both helpers now defer rollback unconditionally; after a successful commit the
rollback returns `sql.ErrTxDone` and has no effect, while callback errors and
panics release the transaction. Nested calls receiving an existing `*sql.Tx`
continue to leave ownership and cleanup to the outer transaction.

Added `TestTransactionCallbacksPanicAndReleaseConnection`, which verifies both
helpers roll back inserted rows and allow subsequent queries after a panic.
The test compiles in the SQLite-stub environment but requires the real SQLite
driver to execute. Non-SQLite unit tests, selected Gateway tests, compile checks,
Race tests, vet, build, and 32-bit test-binary compile checks pass as recorded
for this batch. Real SQLite execution and remote CI remain release gates.

## Persistence sink panic containment (2026-11-04 09:05 UTC)

A further Recorder audit found that `RequestSink.Append` errors were counted, but
an unexpected panic from a sink could escape the middleware's deferred cleanup.
On a normal request this could surface as a panic after the response had already
been written; during handler-panic recovery it could replace the original handler
panic. The Recorder now contains sink panics, increments the same cumulative
`persistence_failures` counter used for returned append errors, and does not expose
panic values. The original handler panic continues to propagate unchanged.

Added `TestMiddlewareContainsPersistenceSinkPanic` and
`TestHandlerPanicIsPreservedWhenPersistenceSinkAlsoPanics`. Both execute without
a database driver. Observability tests and race tests pass; all packages/test files
compile with the compile-only SQLite stub; `go vet ./...`, `go build ./cmd/omnirouter`,
and gofmt pass in that environment. Real SQLite integration, remote CI, and live
Provider checks remain outstanding.

## HTTP writer capability and concurrent migration hardening (2026-11-04 09:12 UTC)

The Recorder response-writer wrapper now documents and tests its optional-interface
contract. It exposes `http.Flusher` only when the underlying writer supports it,
and its `Unwrap()` method lets `http.ResponseController` reach underlying
capabilities such as Hijack and deadline operations without falsely advertising
`http.Hijacker` or `http.Pusher` through direct type assertions. Tests verify both
supported and unsupported Flush/Hijack behavior through `ResponseController`.

The migration runner now obtains SQLite's writer reservation inside each
migration transaction before rechecking the version marker. This closes the
previous check-before-transaction race: a concurrent process waits according to
SQLite's configured busy timeout, then skips a migration whose marker was
committed by the first process. A two-connection concurrent-startup integration
test verifies that both migration calls succeed and exactly five version markers
remain. The integration test is compile-checked only until the real Go SQLite
driver is available. A separate Python SQLite lock probe confirmed that the
no-op UPDATE acquires a writer reservation even when its predicate matches no
row; this is SQL-engine behavior validation, not execution of the Go migration
runner.

Compile-only package checks, TokenUsage/Observability/OpenAI Provider tests,
those unit tests under `-race`, `go vet ./...`, `go build ./cmd/omnirouter`, and
gofmt pass in the isolated local SQLite-stub environment. The real SQLite
concurrency integration test, complete `go test ./...`, remote CI, and live
Provider acceptance remain outstanding.

## Downstream stream terminal-marker correctness (2026-11-04 10:16 UTC)

A Gateway audit found that a generic provider `Event{Done:true}` with
`ExplicitDone:false` was still translated into a downstream `[DONE]` marker on
OpenAI-compatible chat streams. Anthropic and Gemini translators also finalized
their downstream envelopes on that generic event. This could tell clients that
a response completed successfully even though the upstream protocol had not
provided its required explicit terminal marker.

All three streaming entry points now retain any partial usage but return from
the callback without emitting a successful terminal marker or finalizing the
translated envelope when `ExplicitDone` is false. The request is subsequently
recorded as `stream_incomplete`, and `token_usage_final` remains false. Added
`TestGatewayDoesNotEmitSuccessfulTerminalMarkerForNonExplicitDone` for the
OpenAI-compatible route.

The new regression test, selected Gateway unit tests, TokenUsage/Observability/
OpenAI Provider tests, compile-only package checks, `go vet ./...`, `go build
./cmd/omnirouter`, and gofmt pass using an isolated local SQLite compile stub.
The new Gateway regression test also passes under `-race`. A real SQLite Go
driver remains unavailable because DNS/network access to proxy.golang.org is
blocked; therefore the complete SQLite integration suite, including concurrent
migration startup, has not been executed. Remote CI and live Provider acceptance
remain outstanding.

## Response-writer optional interface forwarding (2026-11-04 10:33 UTC)

The Recorder wrapper now implements `io.ReaderFrom` so `io.Copy` can retain the
underlying writer's optimized copy path. It records an implicit 200 status before
forwarding and falls back to `io.Copy` when the underlying writer does not
implement `io.ReaderFrom`. Tests verify the fast path is reached and response
status accounting remains correct. A separate test confirms
`http.ResponseController.Hijack()` reaches a supported underlying `http.Hijacker`
through `Unwrap()` while the wrapper itself does not directly advertise
`http.Hijacker`.

Observability tests and race tests, TokenUsage/Provider tests and race tests,
compile-only checks for all packages/test files, `go vet ./...`,
`go build ./cmd/omnirouter`, and gofmt pass in the isolated SQLite-stub
environment. The real-driver SQLite suite, remote CI, and live Provider
acceptance remain outstanding.
